# mirror-shfmt

OCX mirror for [shfmt](https://github.com/mvdan/sh) — sources GitHub releases, publishes to `ocx.sh/shfmt`.

## Repo layout

| Path | Owner |
|------|-------|
| `mirror.yml` | Hand-edited |
| `metadata.json` | Hand-edited |
| `.github/workflows/mirror.yml` | Generated by `ocx-mirror pipeline generate ci` |
| `scripts/install-branch-protection.sh` | Generated by `ocx-mirror pipeline generate ci` |
| `scripts/README-branch-protection.md` | Generated by `ocx-mirror pipeline generate ci` |

Regenerate after editing `mirror.yml`:

```sh
ocx-mirror pipeline generate ci
```

Drift check (used in CI):

```sh
ocx-mirror pipeline generate ci --check
```

## Pipeline

Workflow runs on `workflow_dispatch`, `push` to `main`, and every 6 hours. Five stages:

1. **discover** — `ocx-mirror pipeline plan` lists new `(version, platform)` work
2. **prepare** — `ocx-mirror pipeline prepare --version V` downloads + bundles per V
3. **test** — `ocx package test` runs per `(V, P, container)` leg, emits JUnit XML
4. **push** — `ocx-mirror pipeline push` aggregates JUnit, publishes greens via `ocx package push --cascade`, writes `run-summary.json`
5. **notify** — `ocx-mirror pipeline notify` posts Discord embed per outcome

Single serial push job = sole cascade-tag writer (R1: prevents cross-run cascade-tag corruption).

## Required secrets

| Secret | Purpose |
|--------|---------|
| `OCX_SH_REGISTRY_PASSWORD` | OCI registry auth for `ocx package push` |
| `DISCORD_WEBHOOK_URL` | Discord channel webhook for notify stage |

## Branch protection

Run once after the first successful workflow run produces all required check names:

```sh
bash scripts/install-branch-protection.sh
```

See `scripts/README-branch-protection.md` for the list of required checks.
